# AI_PLAN.md — 한국어 sLLM 웹 테스트 에이전트 개발 계획서

> 작성일: 2026-04-13
> 개정: 2026-04-13 (v4 — Single-shot Q&A 구조 채택: 컨텍스트 누적 제거로 RPi5 성능 최적화)
> 대상 하드웨어: Raspberry Pi 5 (**8GB 및 16GB** 양 환경 지원)
> 목적: 라즈베리파이5에서 다양한 한국어 sLLM을 **쉽게 선택하고 쉽게 바꿔가며 빠르게 질의-응답해 볼 수 있는** 미니멀 웹 도구

---

## 0. 프로젝트 정체성 (중요)

> **본 시스템은 "간단한 테스트 에이전트"이며, Single-shot Q&A 구조다.**
>
> 라즈베리파이에 설치된 한국어 sLLM을 **한 번에 하나씩, 쉽게 바꿔가며 빠르게 질의-응답해 보는** 미니멀 웹 도구다.
> 각 질문은 **완전히 독립적**으로 처리된다 — 이전 대화 내용은 모델에 전달되지 않는다.
> 이 설계는 RPi5의 제한된 성능(특히 프리필 병목)을 고려해 **응답 속도를 항상 일정하고 빠르게** 유지하기 위함이다.
> 대화 이력 저장, 즐겨찾기, 내보내기, 검색, 비교 모드 같은 "플랫폼 기능"은 만들지 않는다.

### 핵심 가치

| 가치 | 설명 |
|------|------|
| **단순성** | UI는 모델 선택 + Q&A 창 2가지만. 설정도 최소한. 학습 없이 바로 사용 |
| **일정한 속도** | 매 질문은 독립 처리 → 대화가 길어져도 응답 시간이 느려지지 않음 |
| **즉시 전환** | 모델 드롭다운/설정에서 선택 → 바로 전환. 화면 대화 기록은 클리어 (저장 없음) |
| **로컬성** | 모든 추론은 RPi5 내부에서 수행. 외부 API 호출 없음 |
| **다양성** | 한국어 특화부터 다국어까지, 1.5B부터 8B까지 여러 모델을 준비 |
| **응답 중 투명성** | 응답 생성 중 CPU/RAM을 가볍게 표시 (응답 완료 시 업데이트 종료) |

### 설계 트레이드오프 (의도적 선택)

**수용한 제약**: 후속 질문 불가 ("더 자세히 설명해줘", "방금 말한 코드 수정해줘" 등 문맥 이어지는 질의는 동작 안 함). 각 질문은 필요 정보를 모두 포함해 독립적으로 작성해야 함.
**대신 얻는 것**: RPi5에서도 항상 5~20초 이내 응답 시작, 메모리 안정성, 구현 단순성.

## 1. 시스템 아키텍처

### 1.1 전체 구성도

```
┌──────────────────────────────────────────────────────────────┐
│                   Raspberry Pi 5 (8GB or 16GB)                │
│                                                               │
│   ┌────────────┐    ┌─────────────────┐    ┌──────────────┐   │
│   │  Ollama    │◄──►│  Backend        │◄──►│  Frontend    │   │
│   │  Server    │    │  (FastAPI)      │    │  (Chat SPA)  │   │
│   │  :11434    │    │  :8000          │    │              │   │
│   └────────────┘    └────┬────────────┘    └──────────────┘   │
│                          │                                     │
│        ┌─────────────────┼─────────────────────┐               │
│        │                 │                     │               │
│   ┌────┴────┐     ┌──────┴──────┐       ┌──────┴──────┐        │
│   │ Chat    │     │ Model       │       │ System      │        │
│   │ Service │     │ Registry    │       │ Monitor     │        │
│   │ (코어)  │     │ (카탈로그)  │       │ (부가정보)  │        │
│   └────┬────┘     └─────────────┘       └─────────────┘        │
│        │                                                       │
│   ┌────┴────┐                                                  │
│   │ SQLite  │  (모델 설치 상태 캐시 + UI 설정)                 │
│   └─────────┘                                                  │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 컴포넌트

| 컴포넌트 | 역할 | 우선순위 |
|---------|------|---------|
| **Frontend (Chat SPA)** | 채팅 UI, 모델 선택, 설정 패널 | ★★★ (주 기능) |
| **Chat Service** | Single-shot 요청 처리 (system prompt + prompt → ollama 스트리밍 전달), stateless | ★★★ (주 기능) |
| **Model Registry** | `AI-SLLM-MODELS.md` 의 모델 카탈로그를 JSON으로 관리, 설치 상태 추적 | ★★★ (주 기능) |
| **Ollama Server** | LLM 추론 엔진 | ★★★ (인프라) |
| **SQLite DB** | 모델 설치 캐시 + UI 설정 (대화는 저장하지 않음) | ★★ |
| **System Monitor** | 응답 생성 중 CPU/RAM/온도 표시 (응답 완료 시 중지) | ★ (부가 기능) |

### 1.3 사용자 플로우

```
1. 사용자 → 브라우저 접속 (http://<RPi_IP>:8000)
   → 대시보드: "어떤 모델과 대화하시겠어요?" 모델 카드 리스트

2. 사용자 → 모델 선택 (예: EXAONE 3.5 2.4B)
   → 채팅 화면 진입. (첫 선택 시 모델 로딩 진행 표시)

3. 사용자 → 질문 입력 (독립 질의)
   → Backend /api/chat → Ollama 스트리밍 → SSE → 화면 타이핑 효과
   → 응답 하단에 CPU/RAM/온도 실시간 표시 (응답 완료 시 최종값 고정)
   → 이전 질문/응답은 화면에만 남고, 다음 요청에는 전달되지 않음

4. (옵션) 사용자 → 페르소나 프리셋 선택
   → 매 요청에 주입될 system prompt 변경 (화면 대화 기록도 초기화)

5. 사용자 → 모델 변경
   → 확인 모달 → 화면 대화 기록 초기화 → 새 모델로 채팅 시작
```

> **주의**: 단계 3에서 이전 턴은 모델에게 전달되지 않으므로 후속 질문("그걸 더 자세히", "방금 말한 것에 이어서")은 동작하지 않는다. 각 질문은 필요한 맥락을 모두 포함해야 한다.

## 2. 기술 스택

### 2.1 확정 스택

| 계층 | 선택 | 버전 | 선정 사유 |
|------|------|------|-----------|
| **LLM 런타임** | Ollama | 0.6+ | ARM64 네이티브 지원, 모델 관리/추론 통합, REST API 내장 |
| **백엔드** | FastAPI + Uvicorn | 0.115+ / 0.34+ | 비동기 스트리밍(SSE) 최적, 자동 API 문서, 타입 검증 |
| **프론트엔드** | HTML + Vanilla JS + CSS | ES2020+ | 빌드 도구 불필요, RPi에 부담 없음, 단순성 유지 |
| **CSS 프레임워크** | Pico.css 또는 Water.css (CDN) | 2.x | 클래스리스 미니 CSS로 빠른 UI 완성도 확보 |
| **Markdown 렌더링** | marked.js | 12+ | 모델 응답의 마크다운/코드블록 렌더링 |
| **코드 하이라이트** | highlight.js (Korean light theme) | 11+ | 응답 내 코드 가독성 |
| **DB** | SQLite3 | Python 내장 | 파일 기반, 서버 불필요 |
| **시스템 모니터링** | psutil | 6.1+ | CPU/RAM 측정 |
| **온도 측정** | `/sys/class/thermal/thermal_zone0/temp` | OS 내장 | RPi5 SoC 온도 |
| **Python** | CPython | 3.11+ | 가상환경(venv) 사용 |

### 2.2 기각 대안

| 대안 | 기각 사유 |
|------|-----------|
| Flask | 동기 방식 → SSE 스트리밍 처리 번거로움 |
| Gradio | 커스터마이즈 한계, 카드형 UI/대화 이력 구현 어려움 |
| React/Vue | RPi에서 `npm install`+빌드 부담. 본 프로젝트 UI는 단일 페이지로 충분 |
| Streamlit | 상태 관리 모델이 대화형 앱과 맞지 않음, 느림 |
| PostgreSQL | 채팅 이력 규모 대비 과한 의존성 |

## 3. 모델 전략

**상세 카탈로그는 [AI-SLLM-MODELS.md](./AI-SLLM-MODELS.md) 참조.**

### 3.1 요약

- **Tier 1 (한국어 특화, 한국 기업)**: EXAONE 3.5, EXAONE Deep, HyperCLOVA X SEED, Kanana
- **Tier 2 (다국어 고성능)**: Qwen 3, Gemma 3, **Gemma 4**, Llama 3.2
- **Tier 3 (비교/특수)**: Phi-4 Mini, Mistral 7B, SmolLM2

### 3.2 크기별 라인업

| 크기 | 용도 | 하드웨어 | 예시 |
|------|------|---------|------|
| ~0.5-1B | 초경량, 즉답형 | RPi5 8GB 여유 | HyperCLOVA 0.5B, Gemma 3/4 1B, Qwen 3 0.6B |
| **1.5B** | 경량 주력 | RPi5 8GB 표준 | HyperCLOVA 1.5B, Qwen 3 1.7B, SmolLM2 1.7B |
| **3B** | 한국어 품질 주력 | RPi5 8GB 경계 / 16GB 권장 | EXAONE 3.5 2.4B, HyperCLOVA 3B, Qwen 3 4B, Gemma 3/4 4B |
| **7B** | 고품질 대형 | RPi5 16GB 필수 | EXAONE 3.5 7.8B, Qwen 3 8B, Kanana 8B, Mistral 7B |

### 3.3 초기 기본 설치 세트 (공통 3종)

`build.sh` 실행 시 자동 설치:

1. `exaone3.5:2.4b` — 한국어 품질 주력
2. `qwen3:1.7b` — 다국어 경량
3. `gemma3:1b` — 초경량 빠른 응답 (또는 `gemma4:1b` 가용 시)

디스크 약 4GB, 8GB 환경에서도 여유 있게 동작.

## 4. 에이전트 기능 설계 (핵심)

### 4.1 채팅 기본 기능 (Single-shot Q&A)

> **🔑 핵심 원칙: 각 질문은 독립 처리.** 이전 메시지는 모델에 전달되지 않고 화면에만 남는다.

| 기능 | 설명 |
|------|------|
| **독립 질의** | 매 요청은 `[system_prompt (페르소나)] + [현재 질문]`만 모델에 전달. 컨텍스트 누적 없음 |
| **스트리밍 응답** | Ollama → Backend SSE → Frontend 타이핑 효과로 실시간 출력 |
| **마크다운 렌더링** | 모델 응답의 **굵게**, 리스트, 코드블록 자동 렌더링 |
| **코드 복사 버튼** | 응답 내 코드블록에 클릭 한 번으로 복사 |
| **중단 버튼** | 긴 응답 생성 중 사용자가 정지 가능 |
| **재생성 버튼** | 마지막 질문을 동일/다른 모델로 재시도 (이전 응답 버림) |
| **화면 초기화** | "새 대화" 버튼 = 화면의 메시지 표시만 비움 (저장된 컨텍스트 자체가 없음) |
| **이전 질문 복사** | 화면의 과거 질문을 클릭해 입력창으로 복사 → 수정 후 재요청 가능 |

### 4.2 모델 선택/전환

> **🔑 규칙: 모델 변경 = 화면의 메시지 표시만 초기화**
>
> Single-shot Q&A 구조에서 "컨텍스트"는 애초에 누적되지 않으므로, 모델 변경 시 실제로 버릴 서버/모델 상태는 없다.
> 다만 사용자 혼란을 피하기 위해 **화면의 Q&A 기록은 초기화**한다 (이전 모델의 답변과 새 모델의 답변이 뒤섞여 보이지 않도록).

| 기능 | 설명 |
|------|------|
| **첫 진입 모델 카드 그리드** | 대시보드에서 모델을 카드로 표시 (이름/벤더/한국어★/크기/속도/메모리 뱃지) |
| **상단 모델 드롭다운** | 채팅 화면 상단바에 현재 모델명 + ▼. 클릭 시 바로 다른 모델로 전환 |
| **설정 패널 내 모델 변경** | ⚙️ 설정의 "모델" 섹션에서도 동일하게 전환 가능 |
| **모델 변경 확인 모달** | 전환 직전 "화면의 Q&A 기록이 초기화됩니다. 저장되지 않으니 필요 시 미리 복사해 주세요" 경고 |
| **"다시 묻지 않기" 옵션** | 사용자가 익숙해진 뒤 경고 생략 가능 (SQLite settings 테이블에 저장) |
| **화면 초기화** | 전환 직후 메시지 표시 배열을 비움. 백엔드 호출 없음 (누적 컨텍스트가 없으므로) |
| **같은 모델군 크기 전환** | Qwen 3 0.6B↔1.7B↔4B↔8B 등 "같은 모델 다른 크기"도 동일 규칙 적용 |
| **자동 모델 다운로드** | 선택 모델이 ollama에 없으면 pull 진행률 표시 → 완료 후 자동 진행 |
| **8GB 환경 필터링** | RAM 8GB 환경에서는 7B+ 모델 카드를 비활성화 + 대안 추천 표시 |

### 4.3 에이전트 페르소나 (최소 구현)

| 기능 | 설명 |
|------|------|
| **프리셋 페르소나만 제공** | "기본(친절한 도우미)", "한국어 선생님", "코드 튜터", "요리사", "역사 전문가" 5종 고정 |
| **JSON 파일 기반** | `personas/` 디렉토리에 고정 JSON 파일로 관리. DB 저장 아님 |
| **편집/추가 UI 없음** | 사용자 정의 편집/저장 기능은 제외 (단순성 유지) |
| **페르소나 변경 시 대화 클리어** | 모델 변경과 동일 규칙: system prompt 변경은 컨텍스트 재구성이므로 현재 대화 초기화 |
| **추론 모드 토글** | EXAONE Deep, Qwen 3 thinking 모드 on/off (해당 모델에서만 활성) |

### 4.4 시스템 정보 표시 (응답 중에만)

> **핵심 규칙: 응답 생성 중에만 실시간 표시. 응답 완료 시 최종값 고정 후 폴링 중지.**
> psutil 단일 호출 수준으로 시스템 부담을 최소화한다.

| 항목 | 설명 |
|------|------|
| **표시 위치** | 응답 중인 어시스턴트 메시지 **바로 아래 인라인** 작은 글씨 |
| **표시 내용** | "CPU 45% · RAM 4.3GB · 🌡️ 68℃" (스트리밍 중 1초 주기 갱신) |
| **완료 시 고정** | 응답 완료 시 최종값으로 고정. 기존 메타데이터와 병합: "12.4 tok/s · 1.8s · CPU 45% · RAM 4.3GB · 🌡️ 68℃" |
| **폴링 중지** | 응답 완료 즉시 프론트엔드 폴링 interval clearInterval → 백엔드 부하 없음 |
| **설정 토글** | 설정 패널에서 표시 ON/OFF 가능 (OFF 시 tok/s 등 텍스트 메타만 표시) |
| **온도 경고** | 80℃ 이상 시 🌡️ 아이콘을 🔥로 전환 + 툴팁 경고 |

## 6. build.sh / start.sh 설계

### 6.1 build.sh — 환경 구축

1. **하드웨어 자동 감지**
   - RPi5 확인 (`/proc/device-tree/model`)
   - RAM 감지 → **8GB / 16GB 모드 자동 선택**
   - 디스크 여유 확인 (최소 20GB)
   - Python 3.11+ 확인
2. **ollama 설치** (`curl -fsSL https://ollama.com/install.sh | sh`)
3. **Python 가상환경** + `pip install -r requirements.txt`
4. **기본 모델 pull** — 공통 3종 (약 4GB)
5. **추가 모델 인터랙티브 선택**:
   - 8GB 모드 → 3B 이하 한국어 모델 추천 (HyperCLOVA 1.5B, Kanana Nano 등)
   - 16GB 모드 → 7B급 추가 추천 (EXAONE 3.5 7.8B, Qwen 3 8B 등)
6. **DB 초기화** (schema.sql 실행)
7. **완료 리포트**: 설치 모델/디스크/RAM 요약

### 6.2 start.sh — 서버 기동

1. `.venv` 및 ollama 존재 확인
2. ollama 서비스 시작 (11434 응답 대기)
3. `uvicorn backend.main:app --host 0.0.0.0 --port 8000`
4. 접속 정보 출력: `http://<RPi_IP>:8000`

### 6.3 stop.sh — 서버 중지

- FastAPI 종료 (PID 파일), ollama는 선택적 유지

## 7. 데이터베이스 스키마 (최소 유지)

> **대화는 DB에 저장되지 않는다**. 프론트엔드 JavaScript 메모리에만 존재하며 새로고침/모델 변경 시 즉시 소실.
> DB는 오직 **모델 설치 상태 캐시**와 **UI 설정(예: 다시 묻지 않기 플래그)** 용도로만 사용한다.

### 7.1 models (모델 설치 상태 캐시)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | TEXT PK | ollama 모델명 |
| is_installed | BOOLEAN | pull 완료 여부 |
| last_used_at | DATETIME NULL | 최근 사용 시각 (UI 정렬용) |

### 7.2 settings (UI 상태, key-value)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| key | TEXT PK | 설정 키 (예: `skip_model_change_confirm`, `show_system_monitor`, `theme`) |
| value | TEXT | 값 (JSON 직렬화 문자열) |
| updated_at | DATETIME | |

> 모델의 정적 메타데이터(이름/크기/한국어★/라이선스 등)는 `data/models_registry.json`에서 관리.
> 페르소나 프리셋은 `personas/*.json` 파일에서 로드. DB 아님.

## 8. API 엔드포인트

### 8.1 채팅 (주 기능) — Single-shot Q&A

| Method | Path | 설명 |
|--------|------|------|
| POST | `/api/chat` | SSE 스트리밍 응답. **요청 본문**: `{model: string, prompt: string, persona_id?: string}` — 단일 질문만 전달. 백엔드는 `persona_id` → system prompt 로드 후 ollama에 `{system, prompt}` 전송 |
| POST | `/api/chat/stop` | 진행 중 응답 중단 |

**요청 예시**:
```json
POST /api/chat
{
  "model": "exaone3.5:2.4b",
  "prompt": "추석에 대해 알려줘",
  "persona_id": "default"
}
```

**응답 (SSE 스트리밍)**:
```
data: {"type": "token", "content": "추석은"}
data: {"type": "token", "content": " 음력"}
...
data: {"type": "done", "tokens_sec": 12.4, "total_ms": 1800, "eval_count": 145}
```

> **핵심**: `messages` 배열 없음. 각 요청은 이전 요청과 무관하게 독립 처리. 백엔드는 세션 상태를 저장하지 않음.

### 8.2 모델

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/models` | 카탈로그 + 설치 상태 병합 |
| GET | `/api/models/{id}` | 모델 상세 (카탈로그 메타) |
| POST | `/api/models/{id}/pull` | 다운로드 (SSE 진행률) |
| DELETE | `/api/models/{id}` | 삭제 |

### 8.3 페르소나 (조회 전용)

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/personas` | 프리셋 페르소나 5종 목록 반환 |
| GET | `/api/personas/{id}` | 특정 페르소나 상세 |

생성/수정/삭제 엔드포인트 없음 (단순성 유지).

### 8.4 시스템 (응답 중 폴링)

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/system/status` | CPU/RAM/온도 현재값 (프론트엔드가 응답 중에만 1초 주기 폴링) |
| GET | `/api/system/info` | HW 스펙, 설치 모델 요약, ollama 상태 |

### 8.5 설정 (UI 상태)

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/settings/{key}` | 설정 값 조회 |
| PUT | `/api/settings/{key}` | 설정 값 저장 (예: `skip_model_change_confirm=true`) |

```

  { model: "EXAONE 3.5", displayed: [...화면에 표시된 Q&A 쌍들...] }
          │
          │  사용자: 상단 드롭다운 → Qwen 3 4B 선택
          ▼
┌─────────────────────────────────┐

└─────┬───────────────────────────┘

      ▼
① 프론트엔드 displayed 배열 초기화 (DB 저장 없음)
② 상단 모델명 갱신 → "Qwen 3 4B"

```

> Single-shot 구조이므로 "컨텍스트 보존/폐기" 이슈 자체가 없음. 프론트엔드가 관리하는 건 "화면 표시 이력"뿐.

### 9.5 페르소나(System Prompt) 처리 규칙

- 페르소나는 **매 요청의 system prompt**로 주입 (프론트엔드 → 백엔드 → ollama)
- 페르소나는 **모델과 독립**된 설정. 모델 전환해도 유지됨
- 페르소나 변경 시에도 **화면 Q&A 기록은 초기화** (이전 페르소나 응답과 새 페르소나 응답이 섞여 보이지 않도록)
- 백엔드는 `persona_id` → `personas/{id}.json` → `system_prompt` 문자열을 매 `/api/chat` 요청마다 로드하여 ollama에 전달

## 14. 성공 기준 (DoD, Definition of Done)

본 프로젝트가 "완성되었다"고 말할 수 있는 조건:

1. ✅ RPi5 8GB 또는 16GB 에서 `bash build.sh && bash start.sh` 만으로 동작
2. ✅ 브라우저에서 http://RPi_IP:8000 접속 시 모델 선택 대시보드 표시
3. ✅ 한국어 질문 입력 → EXAONE 3.5 2.4B 가 자연스러운 한국어로 스트리밍 응답
4. ✅ **10번째 질문도 첫 질문과 동일한 속도로 응답 시작** (Single-shot 구조 검증)
5. ✅ 모델 드롭다운/설정에서 다른 모델로 전환 시 확인 모달 → 화면 초기화 → 새 모델로 질의 시작
6. ✅ 페르소나 5종 중 선택 시 응답 스타일 변화 체감 (페르소나 변경 시에도 화면 초기화)
7. ✅ 응답 생성 중 응답 메시지 아래에 CPU/RAM/온도가 실시간 표시되고, 완료 시 최종값으로 고정
8. ✅ 8GB 환경에서 7B 모델은 카드가 비활성화되어 선택 불가
9. ✅ 최소 6종 이상의 한국어/다국어 sLLM을 바로 전환해 체험 가능
10. ✅ 05MANUAL.md 만 보고도 타인이 설치/사용 가능

## 15. 구현 시 핵심 주의사항

1. **🔑 Single-shot Q&A 구조**: 매 요청은 독립. 이전 Q&A는 모델에 전달하지 않음. RPi5 프리필 병목을 피하기 위한 의도적 설계. 멀티턴/후속질문 지원 금지 (구현 유혹 차단).
2. **테스트 에이전트가 본질**: "사용자가 쉽게 써보고 쉽게 모델 바꿀 수 있는가?"가 유일한 판단 기준. 이력/검색/비교/내보내기 같은 플랫폼 기능 추가 금지.
3. **모델/페르소나 변경 = 화면 초기화**: 전환 시 화면의 Q&A 표시는 비움. 실제 서버/모델 컨텍스트는 애초에 없으므로 버릴 것도 없음.
4. **대화는 휘발성**: 브라우저 메모리의 "화면 표시" 용도만. 새로고침/모델 변경 시 사라짐. DB 저장 없음.
5. **한 번에 한 모델만 로딩**: ollama 기본 동작 존중. 동시 로딩/비교 모드 구현 안 함.
6. **스트리밍 우선**: 응답 경로를 SSE로. 프론트엔드 타이핑 효과가 체감 속도 핵심.
7. **시스템 모니터링은 응답 중에만**: 응답 시작 시 프론트엔드 1초 폴링 시작, 응답 완료 즉시 중지. 유휴 시 백엔드 부하 0.
8. **한국어 UX**: UI 자체도 한국어 기본. 영어 전환 옵션은 향후 고려.
9. **위험 작업 확인**: 모델/페르소나 변경은 모달 확인 필수. "다시 묻지 않기" 옵션 제공.
10. **설치 진입 장벽 최소화**: `build.sh` 한 번으로 하드웨어 감지→모델 pull→DB 초기화 완결.
11. **8GB 보호**: 8GB 환경에서는 UI 단계에서부터 7B 모델 카드 비활성화 + 대안 추천 모달.
12. **모델 카탈로그 단일 소스**: `data/models_registry.json` 이 유일한 진실. UI/API 모두 이 파일 참조.
13. **채팅 API는 완전 stateless**: 요청 본문은 `{model, prompt, persona_id}` 단일 질문. 서버는 세션 상태 없음.
14. **후속 질문 한계 안내**: 입력창 placeholder 또는 힌트로 "각 질문은 독립 처리됩니다" 표시. 사용자 혼란 최소화.
