## 프로젝트 로드맵

### Phase 1 — VLM 이미지 분석 (완료)
- 단일 이미지 업로드 → Hailo VLM 분석 → 한국어 번역
- 독립 페이지(/vlm) 구성, 모델 프리로드/언로드

### Phase 2 — 동영상 자동 분석 (다음 작업)
- 동영상 업로드 → 자동 프레임 추출 → 순차 분석 → 타임라인 리포트
- 단일 보드(1대)에서 동작, 분석 주기 옵션화

### Phase 3 — 클러스터 확장
- 메인-워커 분산 처리 → 보드 추가만으로 동시 처리량 증가
- 고객 제안: "동시 분석 영상 수를 늘리려면 워커 보드를 추가 구매"

## 예정

### VLM 동영상 분석 파이프라인 흐름
```
동영상 파일 (MP4/MKV/AVI/MOV/WebM)
    │
    ▼ FFmpeg — 설정 간격(기본 30초)마다 프레임 추출

JPEG 이미지 파일들 (00:00, 00:30, 01:00, ...)
    │
    ▼ OpenCV(cv2) — 이미지 디코딩 → numpy 배열 → 336x336 RGB 리사이즈

numpy 배열
    │
    ▼ Hailo NPU — Qwen2-VL-2B 이미지 분석 (~8초/장)

영어 분석 결과
    │
    ▼ RPi CPU/ollama — exaone3.5:2.4b 한국어 번역 (~14초/장)

한국어 분석 결과 → 타임라인별 누적 → 종합 리포트 생성
```

- [ ] FFmpeg로 프레임 추출 — 설정된 간격(기본 30초)마다 이미지 캡처
- [ ] 추출된 프레임을 순차적으로 VLM 분석 + 한국어 번역 자동 수행
- [ ] 분석 주기 옵션값 처리 (사용자가 10초~120초 등 조절 가능)
- [ ] 타임라인별 분석 결과 누적 표시 (00:00, 00:30, 01:00, ...)
- [ ] 동영상 전체 분석 완료 후 종합 리포트 생성
- [ ] 처리 진행률 표시 (예: 35/120 프레임 분석 완료)

#### 동영상 분석 성능 예측 (단일 보드 기준)
| 동영상 길이 | 분석 주기 | 프레임 수 | 예상 처리 시간 |
|------------|----------|----------|--------------|
| 1시간 | 30초 | 120장 | ~56분 |
| 1시간 | 60초 | 60장 | ~28분 |
| 10분 | 30초 | 20장 | ~9분 |

#### 기술 스택
- 프레임 추출: FFmpeg 7.1 (동영상 디코딩/프레임 추출)
- 이미지 전처리: OpenCV 4.13 (numpy 변환, 리사이즈)
- 이미지 분석: Hailo-10H NPU — Qwen2-VL-2B (~8초/장)
- 한국어 번역: RPi5 CPU — exaone3.5:2.4b via ollama (~14초/장)

### 클러스터 분산 처리
메인-워커 구조로 보드 수를 늘려 동시 처리량을 확장한다.

#### 클러스터 아키텍처
```
┌──────────────────────────────────────────────┐
│  메인 노드 (RPi5 + Hailo-10H)                │
│                                              │
│  웹서버 (FastAPI) — 고객 접점, UI 제공         │
│  작업 큐 관리자 — 영상별 작업을 워커에 분배     │
│  결과 DB — 모든 워커의 분석 결과 수집/저장      │
│  리포트 생성 — 타임라인 리포트, PDF/JSON 출력   │
│  워커 역할 겸임 — 자기 자신도 분석 수행         │
│                                              │
└──────────┬───────────────────────────────────┘
           │ 네트워크 (HTTP API)
     ┌─────┼─────┐
     ▼     ▼     ▼
  ┌─────┐┌─────┐┌─────┐
  │워커1 ││워커2 ││워커N │  ← 확장 노드 (RPi5 + Hailo-10H)
  │     ││     ││     │     워커 모듈만 설치하면 즉시 참여
  └─────┘└─────┘└─────┘
```

#### 작업 흐름
```
고객 → 메인 노드에 영상 10개 업로드
         │
         ▼ 작업 큐에 등록 (영상 1~10)
         
메인: 영상1 → 워커1에 분배
      영상2 → 워커2에 분배
      ...
      영상10 → 워커10에 분배
         │
         ▼ 각 워커가 분석 완료 → 결과를 메인에 전송
         
메인 노드 DB에 결과 누적
  ├── 영상1: [00:00 설명, 00:30 설명, ...] ← 완료
  ├── 영상2: [00:00 설명, 00:30 설명, ...] ← 완료
  ├── 영상3: (분석 중... 45%)              ← 진행중
  ...
         │
         ▼ 전체 완료
         
종합 리포트 생성 → 웹 UI 조회 / PDF 다운로드
```

#### 확장 시나리오
| 보드 수 | 동시 분석 영상 | 1시간 영상 10개 처리 시간 |
|--------|--------------|----------------------|
| 1대 | 1개 | ~560분 (순차) |
| 5대 | 5개 | ~112분 (5병렬) |
| 10대 | 10개 | ~56분 (10병렬) |
